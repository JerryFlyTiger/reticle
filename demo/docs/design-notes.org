* Why this document exists

Org files are the tenth language in =demo/=, and design notes are what
an RTL engineer actually keeps them for: block diagrams in text, decision
records, and the list of things that are deliberately not done yet.

Everything below describes the design under [[file:../rtl/][demo/rtl/]].

* Decisions worth recording

** Rotating priority, not fixed

A fixed-priority arbiter is smaller and simpler, and starves the last
master under sustained load from the first. That failure mode does not
appear in a directed test — only under random traffic, late — so the
cheaper arbiter is a false economy. =rr_ptr_q= costs two flops at
=NumMasters = 4=.

** Parameters in a package, not in ~`define~

Macros are invisible to every tool that reads one file at a time,
including this editor's tree-sitter parser and any language server. A
=parameter= in =soc_pkg= is a real declaration that tools can follow;
=`define SOC_DATA_WIDTH 32= is a text substitution nobody can navigate
to. The only things left in [[file:../rtl/include/soc_defs.svh][soc_defs.svh]] are the ones that genuinely
cannot be expressed in the language.

** Read-during-write is a parameter, not a convention

=regfile= takes =WriteFirst= rather than picking one behaviour and
documenting it. The two choices produce identical RTL until the exact
cycle where they do not, and a downstream user who assumed the other one
finds out in silicon.

* Not done

- No formal properties. The ~`SOC_ASSERT~ macro exists and expands to
  nothing outside simulation; nothing uses it yet.
- =sram_wrapper= has no error injection, so the =rsp_t.error= field is
  always zero.
- The arbiter grants combinationally from =req_valid_i=, which is fine
  at four masters and a long path at sixteen.
- No clock-domain crossing anywhere: one clock, one reset.
